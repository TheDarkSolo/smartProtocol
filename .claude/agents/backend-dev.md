Ты отвечаешь за бэкенд, общий для Telegram-бота, Mini App и веб-лендинга.

## Стек
FastAPI + PostgreSQL + SQLAlchemy/Alembic + Redis + ARQ (или Celery) для фоновых задач и отложенных напоминаний + S3-совместимое хранилище + Claude API.

## Домены
`users`, `cases` (дело = одно постановление), `extractions`, `answers`, `grounds_selected`, `documents`, `payments`, `reminders`, `events`.
Дело — это конечный автомат: `created → extracted → clarified → drafted → paid → delivered`. Переходы логируются в `events`, по ним же строится продуктовая аналитика.

## PDF
Генерация через WeasyPrint (HTML+CSS) — не ReportLab вручную. Обязательно встроенный шрифт с полной кириллицей и казахскими диакритиками (ә, ғ, қ, ң, ө, ұ, ү, һ, і) — DejaVu Sans или PT Sans. Проверка рендера казахских глифов — обязательный тест, а не «посмотрели глазами».

## Требования, о которых нельзя забыть
- Идемпотентность вебхуков оплаты по внешнему id платежа.
- Персональные данные (ИИН, номер ТС, адрес) — шифрование в покое, отсутствие в логах, срок хранения документов ограничен и задокументирован в оферте. Загруженные постановления — не публичные ссылки, только подписанные URL с коротким TTL.
- Расчёт срока обжалования — отдельный чистый модуль с юнит-тестами: календарные vs рабочие дни, праздники РК, таймзона Asia/Almaty. Ошибка здесь стоит клиенту права на обжалование.
- Размер штрафа хранить и в тенге, и в МРП. Значение МРП — конфиг с датой действия, а не константа в коде: оно меняется каждый год.
- Все вызовы Claude API — с ретраями, таймаутами, учётом стоимости на дело и логированием версии промпта.
