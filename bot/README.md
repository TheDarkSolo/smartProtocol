# Smart Protocol — Telegram-бот

Вторичный канал продукта (см. [../.claude/agents/tg-bot-dev.md](../.claude/agents/tg-bot-dev.md)
и раздел о платформе в [../ROADMAP.md](../ROADMAP.md)): точка входа для тех,
кто пришёл по ссылке из чата, и в перспективе — канал напоминаний о
незавершённых делах. Основной продукт — сайт (`frontend/`), бот его не
дублирует: вся тяжёлая логика остаётся на бэкенде.

## Получить токен

1. В Telegram напишите [@BotFather](https://t.me/BotFather)
2. `/newbot`, укажите имя и username бота
3. Полученный токен — в `bot/.env`:
   ```
   SPBOT_BOT_TOKEN=ваш_токен
   ```

## Запуск

Бэкенд должен быть поднят (см. [../backend/README.md](../backend/README.md)):

```bash
cd bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.main
```

Поллинг — только для разработки. На проде нужны вебхуки (см. агент
`tg-bot-dev`).

## Что уже есть

- `/start` — приветствие и дисклеймер
- `/language` — переключение ru / kk (хранится в памяти процесса, не переживает рестарт — на проде переезжает в Redis вместе с FSM)
- `/help`
- Приём постановления файлом (PDF/JPG/PNG/HEIC) или фотографией: бот
  скачивает файл у Telegram и пересылает на `POST /api/cases` бэкенда —
  та же точка приёма, что и у веб-загрузки, без дублирования логики

## Чего ещё нет

Разбор постановления, подбор оснований, генерация и выдача жалобы,
напоминания о сроках, оплата. Бот честно говорит об этом пользователю после
создания дела, а не делает вид, что процесс завершён.
